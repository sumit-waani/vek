# Phase 2 stdlib completion: 17 runtime packages for vek

Adds auth (PBKDF2-SHA256), slug, csp, cors, i18n, ratelimit, markdown, sanitize, webhook, cli, compress, http client, mail, jobs, storage, websocket, and flash packages. Each package is a self-contained C file registered through `vek_stdlib.c`, with integration tests exercising the primary paths. The implementations are pragmatic — self-contained crypto (SHA-256, SHA-1, HMAC, PBKDF2), raw TCP HTTP/1.1 client, stored-block DEFLATE, and SQLite-backed job queue — avoiding external dependencies at the cost of feature completeness (no real deflate compression, no HTTPS).

Watch for: path traversal in storage (confirmed), GC rooting gaps in `compress.encode_response` and `http_client.extract_config` where intermediate allocations can collect earlier objects (confirmed), an out-of-bounds `memcmp` in the CSP directive lookup for `form_action` (confirmed), and the sanitize module passing attribute values through unescaped which allows attribute injection XSS (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The storage module writes arbitrary user-supplied keys directly into filesystem paths without sanitizing `../` sequences, so `storage.put("../../etc/cron.d/evil", data)` escapes the storage directory. This is a file-write primitive that should be blocked before shipping.

GC rooting discipline is inconsistent across packages. The http_client and compress modules create `ObjString` temporaries (via `obj_string_new`) without rooting them before the next allocation, meaning a GC triggered by the subsequent `obj_string_new` or `obj_map_new` can collect the unrooted string. The pattern appears in `extract_config`, `compress.encode_response`, and several CORS/CSP helpers, though the latter are lower risk because the only allocations that follow are `obj_map_set` (which may or may not trigger GC depending on load factor).

The sanitize module's allowlist filter reconstructs tags with their attribute values verbatim — no HTML-escaping of the value content. An attacker can break out of the attribute context with a crafted value like `" onclick="alert(1)`, bypassing the sanitizer's purpose.

The CSP directive mapper has a bug: `form_action` (11 chars) is checked against `len == 10` on one line and `len == 11` on the next. The first check reads 11 bytes from a 10-byte buffer — an out-of-bounds read that UB-sanitizers will flag. The second check is the one that actually works.

The jobs module holds handler closures in a static array without informing the GC. If the GC runs and nothing else references those closures, they'll be collected while the handler array still points at them. A `vm_pin` or GC root registration is needed for each handler closure.

1. **Storage path traversal** — `storage.put`/`storage.get`/`storage.delete` allow `../` in keys, enabling reads/writes outside the storage directory. Reject or canonicalize paths containing `..`.
2. **GC rooting in compress.encode_response** — `body_key` and `enc_key` are allocated without rooting; a subsequent `obj_string_new` (for `compressed_body` or `enc_val`) can trigger GC and collect them. Root before next allocation.

4. **Sanitize attribute value not escaped** — Attribute values from the input HTML are written verbatim into the output. Escape `"` and `>` in attribute values to prevent breakout.
5. **CSP form_action OOB read** — `len == 10 && memcmp(key, "form_action", 11)` reads one byte past the buffer. Remove the dead `len == 10` branch.
6. **Jobs handler closures not GC-rooted** — The static `handlers[]` array stores `Value` closures that the GC doesn't know about. Pin or root them on registration.
7. **Auth verify timing oracle on format parsing** — Parsing the hash string returns `VAL_FALSE` at different points depending on how far parsing gets, leaking format information. Not exploitable for password recovery but worth noting for hardening.
8. **HTTP client: no HTTPS, silent nil** — `https://` URLs silently return nil with no indication why. Consider returning an error map or at minimum documenting this.
9. **Compress: deflate stored blocks only** — The inflate function only handles stored blocks (BTYPE=0). Any real deflate stream (from external gzip files) will produce garbage or nil. The function name suggests general inflate support.

## Storage path traversal

`build_path` in `stdlib_storage.c` simply concatenates `storage_dir` + `/` + user-supplied key:

```c
static void build_path(const char* key, char* out, size_t out_size) {
    snprintf(out, out_size, "%s/%s", storage_dir, key);
}
```

No validation rejects keys containing `..`, `/` at the start, or absolute paths. A vek program calling `storage.put("../../../tmp/evil", payload)` writes outside the configured directory. The same applies to `get`, `delete`, and `url`. The fix is to reject any key containing `..` as a path component, or to `realpath()` the result and verify it starts with the storage directory prefix.

## GC rooting gaps in compress and http_client

In `native_compress_encode_response`:

```c
ObjString* body_key = obj_string_new("body", 4);    // NOT rooted
ObjString* enc_key = obj_string_new("encoding", 8); // allocates — can GC, collecting body_key
```

`body_key` is live only in a local variable. If `obj_string_new` triggers a GC cycle while allocating `enc_key`, `body_key` is unreachable (not on the root stack, not in any map yet) and gets freed. The subsequent `obj_map_set(result, body_key, ...)` then uses a dangling pointer.

The same pattern appears in `extract_config`:

```c
ObjString* k_timeout = obj_string_new("timeout", 7);
// ... use k_timeout ...
ObjString* k_headers = obj_string_new("headers", 7); // can GC
```

## Sanitize attribute injection

`native_sanitize_html` reconstructs allowed attributes like this:

```c
san_buf_append(&buf, "=\"", 2);
san_buf_append(&buf, attr_value, attr_value_len);  // raw, unescaped
san_buf_char(&buf, '"');
```

If the source HTML contains `<a href='foo" onclick="alert(1)'>`, the attribute value `foo" onclick="alert(1)` passes through verbatim, breaking out of the `href` attribute in the sanitized output. The fix is to HTML-entity-encode at minimum the `"` character inside attribute values (and ideally `<`, `>`, `&` as well).

## CSP directive lookup bug

```c
if (len == 10 && memcmp(key, "form_action", 11) == 0) return "form-action";
if (len == 11 && memcmp(key, "form_action", 11) == 0) return "form-action";
```

The first line checks `len == 10` but compares 11 bytes — reading one byte past the key buffer. Since `len` is 10, the `key` only has 10 valid bytes. This is undefined behavior. The line is also dead code because `"form_action"` has 11 characters, so `len == 10` can never match it meaningfully. Delete the first line.

## Jobs handler closures and GC

```c
static JobHandler handlers[MAX_HANDLERS];
// ...
handlers[handler_count].closure = args[1];
handler_count++;
```

The `closure` field is a raw `Value` in a static C array. The garbage collector has no visibility into this array — it only traces from VM stack roots, pinned objects, and the GC root stack. If the calling vek code doesn't retain a reference to the handler closure, it becomes eligible for collection. The fix is to call `vm_pin` on the closure's object header when registering it, or to add the handlers array as a GC root source.

## Test coverage gaps

Tests exist for auth, flash, http_client, jobs, markdown, and storage. Not tested: slug, csp, cors, i18n, ratelimit, sanitize, webhook, cli, compress, websocket, and mail. The sanitize module — which has the XSS vulnerability — has no test coverage at all.
