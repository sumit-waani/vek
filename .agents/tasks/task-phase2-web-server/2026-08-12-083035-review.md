# Epoll-based HTTP server runtime for the vek language (v2)

Second review pass. All seven v1 issues were addressed (body size cap, EpollData reuse on Connection/Listener, max_connections, vm.had_error → 500, per-connection timerfd, heap header names, range-based keyword check). Three new concerns surfaced during this pass. Watch for: timer EpollData leak on cancellation (confirmed), use-after-free on simultaneous EPOLLIN+EPOLLOUT after read-handler close (likely), keep-alive connections lose timeout protection after the first request (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The timer subsystem has an ownership gap: `event_loop_add_timer` allocates an EpollData and registers it with epoll, but `event_loop_cancel_timer` only closes the timerfd and frees the Timer struct — the EpollData is orphaned. This leaks one 16-byte allocation per request on keep-alive connections (where the timeout is cancelled after each successful parse) and on every Slowloris close.

The event dispatch loop reads `conn->state` after `handle_read` may have freed the connection via `event_loop_conn_close`. When EPOLLIN and EPOLLOUT fire together on an edge-triggered fd, the EPOLLOUT guard dereferences a freed Connection pointer.

Keep-alive connections receive a timeout on accept but never get a replacement timeout after the first request completes. A client that sends one valid request and then holds the connection idle indefinitely bypasses the Slowloris protection entirely.

<details>
<summary>Issues (3)</summary>

1. **Timer EpollData leak on cancel** — `event_loop_cancel_timer` frees the Timer and closes the fd but never frees the EpollData allocated in `event_loop_add_timer`. Store the EpollData pointer on the Timer struct and free it in `event_loop_cancel_timer`. (confirmed)
2. **Use-after-free on EPOLLIN+EPOLLOUT dispatch** — If `handle_read` closes the connection (freeing conn and ed), the subsequent `conn->state != CONN_CLOSED` check in the EPOLLOUT branch dereferences freed memory. Add a `break` after `handle_read` if the connection was closed, or have `handle_read` return a closed-flag. (likely)
3. **Keep-alive timeout not renewed** — After a request is successfully parsed, the timeout is cancelled and never re-armed. Second and subsequent requests on a keep-alive connection have no idle deadline. Re-arm the timer in `on_data_vek` after consuming a request when `keep_alive` is true. (confirmed)

## Timer EpollData ownership gap

In `event_loop_add_timer`, an EpollData is heap-allocated and passed to `epoll_ctl`:

```c
EpollData* ed = epoll_data_new(TAG_TIMER, timer);
...
ev.data.ptr = ed;
epoll_ctl(loop->epoll_fd, EPOLL_CTL_ADD, tfd, &ev);
```

When the timer fires, the dispatch loop frees this EpollData explicitly:

```c
case TAG_TIMER:
    if (ev_flags & EPOLLIN) {
        handle_timer(loop, (Timer*)ed->ptr);
        free(ed);  // freed here
    }
    break;
```

But when a timer is cancelled before firing (the normal path for request timeouts on successful parse), `event_loop_cancel_timer` does `EPOLL_CTL_DEL` + `close(timer->fd)` + `free(timer)` and never touches the EpollData. The pointer isn't stored on the Timer struct, so it's unreachable. Since every successful HTTP request on a keep-alive connection cancels its timeout timer, this leaks once per request.

Fix: add a `void* epoll_data` field to the Timer struct (mirroring Connection and Listener), store it at creation time, and free it in `event_loop_cancel_timer`.

## Use-after-free in EPOLLOUT dispatch after read-triggered close

In `event_loop_run`, connections that deliver both EPOLLIN and EPOLLOUT in one epoll_wait batch execute:

```c
Connection* conn = (Connection*)ed->ptr;
...
if (ev_flags & EPOLLIN) {
    handle_read(loop, conn, ed);
}
if (ev_flags & EPOLLOUT) {
    if (conn->state != CONN_CLOSED) {  // <-- accessing freed memory
        handle_write(loop, conn, ed);
    }
}
```

If `handle_read` triggers a close (read returns 0, or the data callback calls `event_loop_conn_close`), both `conn` and `ed` are freed inside `event_loop_conn_close`. The subsequent `conn->state` read is undefined behavior — it will manifest as sporadic corruption under heavy load or with ASAN enabled.

A clean fix: have `handle_read` return a boolean indicating whether the connection was closed, and `break` out of the switch before reaching the EPOLLOUT path.

## Keep-alive timeout gap

In `on_data_vek`, after successfully parsing a request:

```c
if (state->timeout) {
    event_loop_cancel_timer(loop, state->timeout);
    state->timeout = NULL;
}
```

For keep-alive connections, `on_write_done_vek` returns without re-arming a timer. The connection sits idle with no deadline, reintroducing the Slowloris surface for any connection that has already sent one valid request. Fix: after consuming the parsed bytes in `on_data_vek`, if `state->keep_alive` is true, start a new timeout:

```c
if (state->keep_alive && server->request_timeout_ms > 0) {
    state->timeout = event_loop_add_timer(loop, server->request_timeout_ms,
                                          on_timeout_vek, conn);
}
```
